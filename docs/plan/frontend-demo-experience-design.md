# 前端演示体验设计

> 状态：设计已确认，实施计划待审核
> 日期：2026-07-26
> 适用范围：Envision 2024 中文 ESG 报告 MVP
> 目标受众：求职面试官、产品验收人员、企业 ESG 使用人员

## 1. 背景

ESG Agent 已具备单份 ESG 报告的上传、metadata 确认、577 项 GRI 核查、复核优先级、人工复核、整改任务和版本化输出能力。Envision 后端已形成冻结基线，当前前端可以完成主要操作，但页面组织和演示叙事仍偏向功能验收，产品价值、数据边界和完整闭环没有在首屏和主路径中充分呈现。

本设计以求职展示为主要场景，同时保证产品验收和 ESG 实际操作所需的真实性。参考 `esg-dashboard` 的导航层级、企业工具信息密度、卡片体系和绿色视觉风格，继续保留 ESG Agent 现有 Next.js、TanStack Query、Recharts 和真实后端 API。

参考仓库只作为视觉与信息架构参考，不复制其静态业务数据、图片动画、虚拟搜索、通知、ESRS、舆情、行业对标或多企业模块。

## 2. 设计目标

### 2.1 主要目标

1. 在 5–8 分钟内讲清楚“上传—分析—复核—整改—输出”的产品闭环。
2. 对外统一使用 577 项 GRI 核查范围，避免内部结构数字干扰产品口径。
3. 清楚区分规则判断、AI 辅助建议和人工复核结论。
4. 让用户能够从汇总指标追溯到 requirement、判断依据和 PDF 证据页。
5. 使用真实 Demo API 和数据库驱动全部业务页面。
6. 保持冻结后端规则和数据模型不变，优先完成前端体验优化。

### 2.2 非目标

本轮不包含以下工作：

- 修改 577 项核查范围、GRI 结构或结果基线。
- 修改 `envision-method-v1.1`、`envision-result-v1.1` 或 `risk-v2.1`。
- 新增数据库迁移。
- 将 Goldwind 重新提升为当前验收重点。
- 增加 ESRS、行业对标、舆情、多企业分析等扩展能力。
- 在前端直接调用外部模型。
- 复制 `esg-dashboard` 的静态数据或技术栈。

## 3. 核心设计原则

### 3.1 报告中心

整个产品围绕当前报告展开。所有业务页面持续显示企业、年份、文件名和分析状态，避免用户进入深层页面后失去上下文。

### 3.2 数据真实

首页、Dashboard、完整核查、复核队列、整改任务和输出版本均由现有 API 实时驱动。前端不硬编码 Envision 的 577、9、54、436、309 等结果，不从静态 JSON 读取产品数据，也不重新计算披露结论或复核优先级。

### 3.3 分层判断

规则、AI 和人工采用独立展示与留痕：

- 规则层展示确定性分析结果。
- AI 层展示已授权外部模型产生的建议；未启用时显示明确空状态。
- 人工层保存追加式复核快照，不覆盖规则判断、AI 建议和历史复核。

### 3.4 可追溯

每个结论需要能够追溯到 requirement、判断依据、缺失项、证据状态和 PDF 页。人工复核在同一工作区完成队列定位、结果比较、原文核证和结论提交。

### 3.5 口径克制

普通产品页面公开以下核心数字：

- 577 项 GRI 核查范围。
- 披露结论分布。
- 复核优先级分布。
- 适用性待确认数量。
- 人工复核进度。

499、78、6、16 等内部结构和裁决数字保留在技术设计、基线审计和方法说明中，不进入常规演示页面。

## 4. 演示叙事与信息架构

### 4.1 全局导航

左侧导航分为两层：

**全局**

- 工作台首页
- ESG 报告

**当前报告**

- 报告总览
- 完整核查
- 人工复核
- 整改任务
- 输出版本

顶部区域显示当前页面标题、当前报告和用户状态。Demo 环境可以显示简洁标识，普通页面不暴露数据库名称、连接地址或隔离实现。

### 4.2 演示主路径

#### 4.2.1 工作台首页

首页承担产品定位、当前工作续接和演示入口：

- 展示当前演示报告。
- 展示 577 项 GRI 核查范围。
- 展示复核优先级和适用性状态。
- 展示上传到输出的六步闭环。
- 根据后端真实状态生成建议下一步。
- 说明 AI 辅助边界。

#### 4.2.2 报告上传

上传相同 PDF 时提供两个明确动作：

- 打开已有报告。
- 重新分析该报告。

底层优先复用已有报告资产并创建新的分析 run，减少重复文件和数据污染。Demo 数据库仍可以通过既有清理流程恢复为空库。

#### 4.2.3 Metadata 确认

展示识别得到的企业名称、报告年份、语言和文件信息。所有关键字段允许修改并要求用户确认，避免把自动识别结果直接当作最终事实。

#### 4.2.4 分析进度

进度页面同时展示：

- 总体完成百分比。
- 当前阶段名称。
- 已完成阶段数。
- 八个阶段各自的等待、进行、完成或失败状态。

后端没有阶段内部进度时，前端不制造逐秒增长。进度条只在真实检查点之间进行短暂视觉过渡。运行进入终态后立即停止轮询和加载动画。

完成状态显示“查看分析结果”和“进入高优先级复核”。部分失败状态展示成功范围、失败阶段及仍可访问的结果。完全失败状态展示原因和重新分析入口。

#### 4.2.5 报告总览

报告总览服务于求职展示和验收快速判断：

- 577 项核查范围。
- 披露结论分布。
- 高、中、低复核优先级分布。
- 适用性待确认数量。
- 规则、AI、人工三层完成状态。
- 正式输出门禁。

页面明确说明复核优先级用于安排人工处理顺序，不代表企业 ESG 风险。

#### 4.2.6 完整核查

完整核查表通过分页或虚拟化访问全部 577 项，不要求一次渲染 577 行。表格至少支持：

- requirement 标识。
- 主题。
- 当前披露结论。
- 复核优先级。
- 复核状态。
- 证据页。
- 分页、首尾访问和总数。

点击条目进入对应判断详情或人工复核工作区。

跨全部 577 项的全局搜索和组合筛选需要新增后端只读查询参数。本轮为保持后端冻结并加快 MVP 验收，不实施全局筛选，也不提供只能筛选当前页的误导性交互；该能力登记为非阻断后续项。

#### 4.2.7 三栏人工复核

复核工作区采用三栏结构：

- 左栏：高优先级或适用性待确认队列、数量和进度。
- 中栏：规则判断、AI 建议和人工复核表单。
- 右栏：PDF 证据页、翻页和缩放。

点击队列项目只更新当前 requirement 和右侧证据页，不触发浏览器下载。人工复核提交后产生追加式快照，并刷新当前详情、队列进度和报告统计。

高优先级队列完成只代表该队列已处理，不表示全部 577 项均已人工确认。

#### 4.2.8 整改任务与输出

整改任务从缺失项或人工复核结论创建，展示责任人、状态、截止日期和关联 requirement。

输出版本区分草稿与正式版本：

- 草稿可以在门禁未满足时生成。
- 正式输出需要满足后端定义的门禁。
- 门禁未满足时解释缺失条件。
- 历史版本保持可追溯。

## 5. 视觉系统

### 5.1 整体框架

- 固定左侧导航。
- 顶部报告上下文。
- 主内容区根据场景使用卡片、表格或三栏布局。
- 克制的企业绿色主题。
- 中等偏紧凑的信息密度。
- 主要操作使用明确动词。

### 5.2 颜色语义

| 语义 | 颜色 |
|---|---|
| 品牌、主要操作、完成 | 深绿色 |
| 高复核优先级 | 红色 |
| 中复核优先级 | 琥珀色 |
| 低复核优先级 | 绿色或中性绿色 |
| 适用性待确认 | 蓝色 |
| 等待、未启用、辅助信息 | 灰色 |

颜色必须配合文字标签使用。同一种颜色在全站保持同一业务语义。

### 5.3 核心组件

- `ReportContext`：企业、年份、文件名和分析状态。
- `MetricCard`：指标值、业务口径和解释。
- `StatusBadge`：披露结论、复核优先级、适用性和复核状态。
- `WorkflowSteps`：上传到输出的六步闭环。
- `NextActionCard`：根据真实状态生成下一步。
- `DataTable`：分页、首尾访问、总数、空状态和加载状态。
- `EvidenceLink`：证据页入口。
- `PdfEvidenceViewer`：页内预览、翻页和缩放。
- `DecisionLayer`：规则、AI、人工三层判断。
- `ExportGate`：草稿和正式输出门禁。

这些组件负责统一表现和交互，不承担冻结规则的重新计算。

### 5.4 响应式策略

| 视口 | 设计行为 |
|---|---|
| 1440px 及以上 | 完整侧栏和三栏复核 |
| 1024–1439px | 收窄侧栏，PDF 改为可切换面板 |
| 768–1023px | 侧栏折叠，表格允许横向滚动 |
| 768px 以下 | 保证基本可读和操作，不作为主要演示设备 |

主要验收视口为 1440×900，同时检查 1920×1080 和 1024×768。

### 5.5 可访问性

- 正文和关键状态满足基本对比度要求。
- 状态同时提供颜色和文字。
- 所有按钮使用明确动词。
- 加载、成功、空数据和错误均有可识别反馈。
- 键盘焦点保持可见。
- 表格标题、表单标签和按钮具备正确语义。

## 6. 动态数据与状态流转

### 6.1 业务状态流

```text
上传报告
  → 确认 metadata
  → 创建分析 run
  → 八阶段分析
  → 报告总览
  → 人工复核
  → 整改任务
  → 版本化输出
```

每个页面消费后端对应状态，不在前端推断后续业务结果。

### 6.2 查询与缓存

- 继续使用 TanStack Query 管理请求、加载、错误和缓存。
- 报告、run、Dashboard、复核队列、详情、整改任务和输出版本使用独立查询键。
- 人工复核成功后，只刷新受影响的详情、队列和统计。
- 页面刷新和直接访问 URL 后从后端恢复真实状态。
- 关键业务状态不依赖浏览器内存保存。

### 6.3 重复上传和并发分析

重复上传响应需要显示“报告已存在”，并提供打开已有报告和重新分析两个动作。

同一报告存在运行中的 run 时禁止重复启动，显示“该报告正在分析”和“查看分析进度”。前端不得通过重复点击创建竞争任务。

### 6.4 AI 辅助

- 前端不直接持有模型密钥。
- 外部模型调用由后端完成并记录。
- 用户显式授权后才允许调用。
- AI 建议包含模型、版本、时间和依据。
- 无建议时如实显示“本次分析未启用外部模型”。
- AI 输出只能作为分析辅助。

### 6.5 PDF 证据

- 通过现有证据页接口加载。
- 队列切换只更新右侧页面。
- 不使用触发下载的导航方式。
- 加载失败时保留中间判断区域。
- 失败状态展示页码、错误和重试入口。
- 翻页和缩放属于前端交互，不改变后端数据。

## 7. 异常状态

| 场景 | 页面处理 |
|---|---|
| 重复上传 | 打开已有报告或重新分析 |
| 已有 run 运行中 | 查看当前分析进度 |
| Metadata 缺失 | 标记字段并要求确认 |
| 分析部分失败 | 展示成功范围和失败阶段 |
| 分析完全失败 | 展示原因和重新分析入口 |
| Dashboard 数据为空 | 说明原因并提供返回入口 |
| PDF 页面加载失败 | 页面内重试，不触发下载 |
| AI 未启用或失败 | 保留规则结果并显示边界 |
| 复核提交失败 | 保留表单内容并允许重试 |
| 输出门禁未满足 | 解释条件并只允许草稿 |
| API 不可用 | 显示服务异常，禁止空白页面 |

## 8. 验收方案

### 8.1 完成标准

| 层级 | 验收目标 |
|---|---|
| 数据准确 | 页面数字、状态和详情与 Demo API 一致 |
| 业务闭环 | 上传、分析、复核、整改和输出连续可用 |
| 交互可靠 | 无错误下载、无限转圈、状态残留和错误跳转 |
| 展示质量 | 5–8 分钟内能讲清产品价值和 AI 边界 |

自动化测试通过后仍需在真实 Demo 数据库中执行完整人工验收路径。

### 8.2 页面验收矩阵

| 页面 | 主要检查点 | 通过标准 |
|---|---|---|
| 工作台首页 | 当前报告、577 口径、下一步 | 数据真实，入口可操作 |
| 报告列表 | 空状态、已有报告、重复报告 | 状态和按钮含义明确 |
| 上传页面 | 相同 PDF、文件错误 | 可打开已有报告或重新分析 |
| Metadata | 企业、年份、语言 | 识别结果可修改并确认 |
| 分析进度 | 八阶段、百分比、失败状态 | 完成后停止动画并显示结果入口 |
| 报告总览 | 结论、优先级、适用性 | 与 API 和冻结基线一致 |
| 完整核查 | 577 总数、分页、首尾访问 | 可访问全部项目 |
| 人工复核 | 队列、判断、PDF、提交 | 页内核证并产生追加式快照 |
| 整改任务 | 创建、编辑、关联条款 | 字段完整且状态可追踪 |
| 输出版本 | 草稿、门禁、历史版本 | 版本可区分，正式输出受门禁控制 |

### 8.3 自动化验证

每个实施批次先运行相关测试。全部前端修改完成后运行：

```powershell
cd frontend
pnpm typecheck
pnpm test
pnpm build
```

需要新增或加强的测试：

- 导航和当前报告上下文。
- Dashboard 指标转换和空状态。
- 重复上传 409 的两种操作。
- 运行中 run 的并发提示。
- 分析完成后停止轮询。
- 部分失败和完全失败页面。
- 复核状态中文映射。
- 点击队列不会触发 PDF 下载。
- 规则、AI、人工三层显示。
- 复核成功后的缓存刷新。
- 577 表格总数、分页、首尾访问和复核跳转。
- 输出门禁提示。

最终运行后端全量测试和 Envision 577 gate，确认前端优化没有影响 API 契约和冻结基线。

### 8.4 人工验收

使用独立 Edge 或 Chrome，不使用 Codex 内置浏览器。检查：

- 1440×900、1920×1080 和 1024×768 视口。
- 内容截断、重叠和异常滚动。
- 状态颜色和文字的一致性。
- 加载、空数据、错误和成功状态。
- 返回、刷新和直接访问 URL 后的状态恢复。
- PDF 是否始终在页面内加载。
- 所有按钮是否产生明确反馈。
- 普通页面是否暴露内部结构数字。

## 9. 求职演示脚本

### 9.1 第 1 分钟：产品定位

在首页说明 ESG Agent 面向企业 ESG 团队，将一份报告转换为可追溯的 GRI 核查、人工复核、整改任务和版本化输出闭环。展示 577 项核查范围和六步流程。

### 9.2 第 2 分钟：上传和数据边界

上传 Envision 2024 中文 ESG 报告，展示 metadata 识别与人工确认、重复报告重新分析、Demo 数据隔离和外部模型授权边界。

### 9.3 第 3 分钟：自动分析

展示八阶段进度，说明分析完成后得到 577 项可追溯核查结果。

### 9.4 第 4 分钟：报告总览

展示披露结论、复核优先级、适用性待确认、三层完成状态和正式输出门禁。

### 9.5 第 5–6 分钟：三栏复核

选择 GRI 2-5-a，展示队列定位、规则判断、AI 状态、PDF 第 77 页和人工复核快照。说明高优先级完成不等于全部 577 项均已人工确认。

### 9.6 第 7 分钟：整改与输出

从缺失项创建整改任务，展示责任人、截止时间和关联 requirement，随后生成草稿输出并说明正式版本门禁。

### 9.7 第 8 分钟：产品与技术总结

集中说明 577 项确定性基线、规则—AI—人工分层架构、Demo 数据隔离、证据追溯和完整测试体系。

## 10. 实施优先级

1. 应用外壳、导航和报告上下文。
2. 工作台首页。
3. 报告总览。
4. 三栏人工复核。
5. 报告列表、上传、metadata 和分析进度。
6. 完整核查表。
7. 整改任务和输出版本。
8. 空状态、错误状态、加载状态和响应式适配。

前三项决定求职展示的第一印象；后五项保证完整验收路径。

## 11. 后端冻结边界

前端实施期间保持以下内容冻结：

- 577 项产品核查口径。
- `envision-method-v1.1`。
- `envision-result-v1.1`。

## 12. 停止条件

出现以下情况时暂停前端扩展并定位根因：

- 页面数据与冻结基线不一致。
- 需要修改 GRI 结构、结果或复核优先级规则。
- 需要新增数据库迁移。
- 人工复核覆盖历史快照。
- 外部模型未经授权被调用。
- 原始报告或标准资产可能被覆盖。
- Demo 环境连接到正式数据库并产生写入。

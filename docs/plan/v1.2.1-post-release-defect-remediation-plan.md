# v1.2.1 发布后缺陷修复实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: 使用 `executing-plans` 按任务顺序执行；涉及行为修复时使用 `test-driven-development`；宣布完成、提交或发布前使用 `verification-before-completion`。所有步骤使用复选框跟踪。

**目标：** 在不扩展 OCR、RAG、LLM 或企业化功能的前提下，修复 v1.2 发布后发现的运行版本不一致、产品/回归数据环境混用、复核人错误回填和用户界面技术字段暴露，并形成可验证的 v1.2.1 补丁候选。

**架构：** 保留 `esg_agent` 作为开发与长期回归库，普通产品演示统一连接 `esg_agent_demo` 和独立 demo runtime；不删除或迁移已有报告。后端 health 增加非敏感运行环境标识，前端对审计接口版本不一致给出明确提示；复核人每次进入均为空；主产品链路中的 `requirement` 等开发术语统一转换为中文产品表达。

**技术栈：** FastAPI、Pydantic Settings、PostgreSQL、React/Next.js、TypeScript、TanStack Query、Vitest、pytest、Chrome。

**计划状态：** 已批准编写，尚未批准执行。执行会形成 `v1.2.1` 补丁提交；不得移动或覆盖既有 `v1.2` 标签。

## 一、已确认问题与根因

| 编号 | 用户现象 | 根因 | 严重度 | 处理工作包 |
|---|---|---|---|---|
| DEF-001 | 首页进入“确认报告信息”后企业、年度和页数为空 | 8000 服务连接 `esg_agent` 长期回归库；首页固定选择按创建时间倒序的第一条报告；`*-regeneration-*` 技术记录没有 metadata 和 page count | P1 | 运行环境隔离 |
| DEF-002 | AI 授权说明出现 `requirement`、`证据 ID` | 前端用户文案直接写入开发字段名 | P2 | 术语收口 |
| DEF-003 | 进度页显示 `GRI requirement 匹配` | 阶段中文映射未完全本地化 | P2 | 术语收口 |
| DEF-004 | 复核人默认显示“Chrome 自动验收” | `ReviewerGate` 从 localStorage 读取并跨报告复用名称；自动验收写入的名称被保留 | P1 | 身份安全 |
| DEF-005 | 完整范围出现 `Requirement` 和 `Requirement ID` | 表头和搜索 placeholder 直接硬编码开发术语 | P2 | 术语收口 |
| DEF-006 | 报告审计记录加载失败 | 8000 后端进程启动于报告审计接口提交之前；运行中的 OpenAPI 不含 `/api/reports/{report_id}/audit`，请求实际返回 404 | P1 | 运行版本同步与错误可见性 |

补充现场事实：

- 当前 `main` 与 `origin/main` 一致，工作区干净。
- `v1.2` 固定指向提交 `876859f`。
- 当前 8000 后端进程没有 `pending` 或 `running` run。
- 当前后端代码已经包含报告审计接口，当前运行进程没有重新加载该代码。
- `esg_agent` 中存在 70 条长期验收和 regeneration 报告记录；禁止为了修复界面而删除。
- `esg_agent_demo` 中存在 6 条完整产品报告，最新记录具备公司、年度和页数，可用于普通产品运行。

## 二、方案比较与选择

### 方案 A：前端按 report ID 排除 `regeneration`

优点是改动小。缺点是依赖技术命名约定，新的回归工具或其他内部记录仍可能进入首页，也会让前端承担数据来源判断。

**结论：不采用。**

### 方案 B：给 reports 表增加 `record_source` 或 `visibility`

优点是长期语义清晰。代价是新增 migration、API 字段、历史数据回填和完整数据库兼容验证，超出补丁版本需要的最小范围。

**结论：v1.2.1 不采用，企业化或多工作区阶段再评估。**

### 方案 C：运行环境隔离并增加可观察身份

普通产品演示使用 `APP_ENV=demo`、`esg_agent_demo` 和 demo runtime；开发/回归工具继续使用 `esg_agent`。health 公开 `app_env`，启动验收同时检查 OpenAPI 是否包含当前版本关键路由。

优点是复用现有环境安全校验，不改数据库结构，不删除历史数据，同时解决首页技术报告污染和服务版本难以识别的问题。

**结论：采用。**

## 三、冻结边界

本计划允许：

- 增加 health 的非敏感 `app_env` 字段。
- 修改前端用户文案和错误提示。
- 删除复核人 localStorage 记忆行为。
- 更新前后端测试、OpenAPI 生成类型和运行文档。
- 在没有活动 run 时重启 3000/8000 本地服务。

本计划禁止：

- 删除、覆盖或批量修改 `esg_agent`、`esg_agent_demo` 中的报告、run、assessment、snapshot、action、export 或 audit。
- 新增 Alembic migration、表或正式业务字段。
- 修改 GRI `577/499/78/0` 结构、规则、证据、风险、适用性或正式导出口径。
- 修改 DeepSeek 模型、Prompt、候选筛选、guardrail 或调用默认值。
- 调用 DeepSeek、SiliconFlow、OCR、VLM。
- 移动、重打或删除 `v1.2` 标签。
- 自动 push 或创建 `v1.2.1` 标签。

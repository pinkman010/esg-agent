# 侧边栏图片显示一致性修复设计

## 背景与问题

报告工作区所有桌面端页面共用 `AppShell` 的侧边栏图片。当前侧边栏作为 CSS Grid 子项，会被右侧主内容撑高；图片使用 `fill` 与 `object-cover`，因此页面越长，图片裁切比例变化越大。报告总览和完整核查内容明显更长，导致光伏主体消失、背景变成浅色局部；完整核查在表格加载前后还会发生视觉跳变。

## 目标与边界

- 侧边栏图片在所有报告页面保持相同的视口高度、裁切位置和视觉强度。
- 侧边栏导航保持现有信息结构、激活状态和可访问性。
- 不修改主内容、路由、API、后端、业务口径或视觉素材。
- 移动端继续隐藏桌面侧边栏。

## 方案比较

1. **视口高度的 sticky 内层容器（采用）**：让外层 `aside` 随 Grid 保持布局占位，内层容器固定为 `calc(100vh - 4rem)` 并在顶部导航栏下粘滞。图片、遮罩和导航都放入该容器。裁切与页面总高度解耦，同时长页面滚动时导航保持可用。
2. **固定 `background-size`**：能够稳定图片比例，但需要将 Next.js `Image` 改为 CSS 背景，失去现有图片优化路径，且超长侧栏下方可能出现空白或重复。
3. **为长页面单独设置图片样式**：改动小，但会引入路由分支和重复规则，后续新增页面仍可能复发。

## 实现设计

- 保留现有外层 `aside` 作为网格列和边框容器。
- 新增 `sticky top-16 h-[calc(100vh-4rem)] overflow-hidden` 内层容器。
- 将背景图片、两层遮罩和 `ReportContextNav` 移入内层容器。
- 保持图片 `object-position`、透明度和颜色处理参数不变，避免扩大视觉调整范围。

## 测试与验收

- 组件测试先断言侧栏存在固定视口高度的 sticky 容器，并验证现状下测试失败。
- 实现后运行 `app-shell` 目标测试、前端全量测试、类型检查和生产构建。
- 在桌面端对比报告总览、完整核查、人工复核、整改任务、输出版本和审计时间线。
- 验收标准：六个页面首屏侧栏显示同一裁切；完整核查数据加载前后图片不跳变；导航可见且激活状态正确。

## 风险与控制

- 小高度屏幕可能使导航内容接近视口底部；现有六个入口在当前尺寸内可容纳，视觉验收覆盖常用桌面视口。
- sticky 行为依赖顶部栏高度 `4rem`；该值与当前头部 `h-16` 一致，后续若调整头部高度应同步维护。

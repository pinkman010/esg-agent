# 低质量 OCR 证据降级展示设计

## 1. 背景与目标

人工复核页会直接展示后端返回的 `evidence_preview`。Envision 2024 报告第 77 个 PDF 页经过显式 OCR 后，产生了包含大量错字、断词和无意义英文字符的识别文本。该文本在 API、数据库和前端之间没有发生编码转换错误，问题来源是 OCR 识别质量不足。

当前 OCR 默认关闭，异常只在显式 OCR 试点 run 中复现；同页 OCR 证据已带有 `source_method=ocr` 和 `quality_flags=[needs_manual_review]`。本轮目标是使用现有字段对低质量 OCR 证据进行降级展示，避免把原始识别噪声当作普通可读证据呈现，同时保留审计追溯和 PDF 原页核对能力。

## 2. 方案比较

### 方案 A：前端降级展示并保留折叠原文（采用）

人工复核页识别 `source_method=ocr` 且包含 `needs_manual_review` 的证据，默认显示质量警告和 PDF 原页核对操作，原始 OCR 预览放入折叠区域。普通证据继续直接显示预览。

优点：直接解决用户可见问题，复用现有 API 字段，不解冻后端，不删除审计内容。代价：底层 OCR 准确率不发生变化，原始文本仍只适合人工追溯。

### 方案 B：只隐藏 OCR 原文

优点：实现最短。代价：审计人员无法在页面查看原始 OCR 输出，容易误以为系统没有保存识别结果。

### 方案 C：立即建设通用 OCR 质量门禁

优点：可以同时约束后端证据路由。代价：需要 OCR gold、质量指标、后端语义变更和完整基线重跑；当前只有一个试点页，容易针对单一样本过度设计。

## 3. 展示规则

在 `frontend/components/review/assessment-detail.tsx` 的“规则证据”区域按以下顺序处理每条证据：

1. 所有证据继续显示 `page_label`，点击“核对 PDF 原页”时调用现有 `onEvidencePage(source_pdf_page)`。
2. `pdfplumber` 显示来源标签“PDF 原文”；`ocr` 显示“OCR 识别文本”；其他来源使用现有英文枚举值作为审计兜底，不新增业务翻译范围。
3. 当 `source_method === "ocr"` 且 `quality_flags` 包含 `needs_manual_review` 时，显示警告：“OCR 识别质量不足，请核对右侧 PDF 原页。”
4. 低质量 OCR 的 `evidence_preview` 默认收起，使用原生 `details/summary` 提供“查看原始 OCR 识别文本”。展开操作不能触发 PDF 翻页。
5. 不满足上述条件的证据继续直接显示 `evidence_preview`，保持当前操作习惯。

现有证据项使用整个 `button` 包裹内容。实施时将每个证据项调整为非交互容器；PDF 跳转按钮与原生折叠区域作为同级元素，避免在 `button` 内嵌套 `details` 造成无效 HTML 和键盘交互冲突。

## 4. 数据与行为边界

本轮只读取已有的 `source_method`、`quality_flags`、`page_label`、`evidence_preview` 和 `source_pdf_page`：

- 不修改 API schema、生成类型、后端、数据库或历史 run；
- 不删除、改写或自动纠正 OCR 文本；
- 不改变规则结论、证据数量、风险、适用性、人工快照、AI 候选或正式导出；
- 不改变 PDF 查看器的页码语义；
- 不把低质量 OCR 包装成经过校正的报告原文。

底层 OCR 准确率、通用质量评分和规则证据准入继续作为后续独立决策，需积累多类真实扫描样本和 OCR gold 后再启动。

## 5. 可访问性与响应式

- PDF 原页核对使用语义化 `button`，可通过键盘聚焦和触发。
- 原始 OCR 预览使用原生 `details/summary`，保留浏览器键盘与辅助技术支持。
- 来源标签和质量警告使用可见文字，不只依赖颜色或图标。
- 长 OCR 文本允许正常换行，不产生人工复核中栏的水平滚动。
- 移动端“队列／判断／证据”三栏切换行为保持不变。

## 6. 测试与验收

### 6.1 自动测试

在 `frontend/components/review/assessment-detail.test.tsx` 先新增失败测试，再完成实现：

1. 低质量 OCR 默认显示来源标签和质量警告；
2. 原始 OCR 预览位于折叠区域，默认未展开；
3. 点击“核对 PDF 原页”传出正确页码；
4. 展开原始 OCR 文本不会触发 PDF 页码回调；
5. `pdfplumber` 证据显示“PDF 原文”并直接展示预览；
6. 普通证据的 PDF 页码回调保持可用。

新增测试通过后运行人工复核相关测试，再运行前端全量测试、typecheck、production build 和 lint。

### 6.2 浏览器验收

使用现有显式 OCR 试点报告打开人工复核页并定位 `GRI 2-5-b-ii`：

- 默认不再直接展示异常 OCR 字符串；
- 页面明确说明 OCR 识别质量不足；
- 可以跳转到 PDF 第 77 页核对原文；
- 可以主动展开原始 OCR 预览用于审计；
- `pdfplumber` 证据仍可直接阅读；
- 桌面端和约 390px 窄屏均无水平滚动或交互遮挡；
- 控制台没有本轮新增错误。

## 7. 文档、提交与发布边界

实现完成后同步更新前端视觉迁移／验收记录，说明 OCR 证据使用现有质量标志执行降级展示。设计、实施计划、代码测试和验收文档按职责分别提交，暂不 push。

本修复作为 `v1.3.2` 前端补丁候选的一部分，不单独修改版本号。完成后继续执行 ESG 报告入口页主图补齐，最后统一判断 `v1.3.2` 是否达到版本冻结条件。

## 8. 终止条件

低质量 OCR 证据默认降级、原始文本可追溯、PDF 原页可核对、普通证据无回归，并通过自动门禁和浏览器验收后，本工作包终止。本轮不扩展为 OCR 引擎调参、通用质量评分、后端证据准入或历史数据迁移。
